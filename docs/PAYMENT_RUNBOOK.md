# 토스페이먼츠 테스트 결제 실행서

## 설정

`SUPER_ADMIN`으로 `/admin/integrations`에 접속해 테스트 client key와 secret key를 입력합니다. 키 원문은 서버에서 AES-256-GCM으로 암호화되며, 이후 마지막 네 자리만 표시합니다. `연결 검사`는 실제 API 인증을 확인하지만 결제·과금 요청은 만들지 않습니다.

## 결제

1. 고객 로그인과 장바구니 상품이 필요합니다.
2. 서버가 상품 DB에서 금액을 다시 계산하고 고객 소유 주문을 만듭니다.
3. 성공 리다이렉트의 금액·주문번호를 DB와 대조합니다.
4. 승인 호출이 타임아웃되면 paymentKey 조회 API로 최종 상태를 재확인합니다.
5. 같은 고객 소유 주문만 승인하며 다른 고객 주문번호는 찾을 수 없습니다.

## 웹훅

토스 개발자센터의 `PAYMENT_STATUS_CHANGED` URL을 다음으로 등록합니다.

```text
https://<public-host>/api/payments/toss/webhook
```

일반 결제 웹훅에는 임의 서명 헤더를 가정하지 않습니다. 수신 후 paymentKey 조회 API를 다시 호출하고 주문번호·금액을 대조한 뒤 상태를 반영합니다. `tosspayments-webhook-transmission-id`를 DB 고유 키로 저장해 재전송을 멱등 처리합니다.

## 취소

관리자 주문 화면은 취소 직전 토스 결제 원장 상태와 전액 취소 가능 금액을 다시 조회합니다. 취소 요청에는 UUID 멱등 키와 사유가 필요하며, 같은 키의 재시도는 이중 취소하지 않습니다. 실결제·부분 취소는 지원하지 않습니다.
